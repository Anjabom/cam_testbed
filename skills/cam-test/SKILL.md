# cam-test — 워크스페이스 밖에서 카메라 인지를 시험한다

대상 워크스페이스를 import 하지 않는다. `ros2 run` 서브프로세스로 띄우고 DDS 로만 대화한다.
영상을 이미지 토픽으로 밀어 넣고, 나오는 토픽을 전부 기록해 **재고 · 그리고 남긴다**.

**테스트베드가 대상을 아는 통로는 계약(`contracts/*.yaml`) 한 파일뿐이다.**
워크스페이스 1개 = 계약 1개. 새 워크스페이스를 붙일 때도 테스트베드를 복사하지 않는다.

## ★합격/불합격을 찍지 않는다★

예전에는 시나리오 YAML 의 `checks:` 가 임계값으로 판정했다. 그 숫자는 결국 첫 런의
실측에서 나온 것이라 근거가 약했고, 리포트 맨 위의 「13/13 통과」한 줄이 나머지를
안 읽게 만들었다. 지금 이 도구가 내놓는 것은 **관측값과 그림뿐**이다:

- `report.md` — 신호 통계 · 받는 쪽 게이트 통과율 · θ 품질 · 단계 전이 · 노드 로그 · 계약 정합
- `signals.csv` — 프레임별 원표
- **디버그 영상** — 대상 노드가 그린 그림 (사후에 만들 수 없는 유일한 기록)

**좋은지 나쁜지는 네가 그 데이터를 읽고 말한다.** 임계값을 지어내지 마라.

## 0단계 — 어디서 돌릴지부터 정한다

```bash
#  ★원본 저장소를 먼저 찾는다 — CLAUDE_PLUGIN_ROOT 보다 앞이다★
#  플러그인 설치본은 원본의 복사본일 수 있다. 그러면 local.yaml(가중치 경로,
#  git 제외라 복사본엔 아예 없다)·runs/ 가 갈라져 ★같은 머신에 테스트베드가
#  둘★ 이 된다. 런 결과가 플러그인 캐시에 쌓이면 "어제 그 런"을 다시 못 찾는다.
TB=""
for c in "$HOME/cam_testbed" "$CLAUDE_PLUGIN_ROOT"; do
  [ -n "$c" ] && [ -d "$c/tb" ] && [ -d "$c/contracts" ] && { TB="$c"; break; }
done
WS="$(pwd)"                                        # 시험 대상 = 지금 있는 워크스페이스
[ -n "$TB" ] && echo "테스트베드: $TB" || echo "테스트베드를 못 찾았다"
```

**`$TB` 를 못 찾으면 여기서 멈추고 사용자에게 위치를 묻는다.** 스킬은 ROS 2·GPU·가중치·
테스트베드 자체를 설치해 주지 못한다 — 없으면 없다고 말하는 것이 맞다.

모든 `tb.run` 명령은 `cd "$TB"` 하고 친다 (`python3 -m` 이 그 디렉터리를 sys.path 로 쓴다).
ROS 언더레이도 먼저 source 한다:

```bash
source /opt/ros/humble/setup.bash
cd "$TB" && [ -f local.yaml ] || cp local.yaml.example local.yaml
```

`local.yaml` 을 새로 만들었으면 **가중치 경로를 이 머신에 맞게 고쳐야 한다** —
`.example` 의 경로는 남의 머신 것이다. 사용자에게 가중치 위치를 묻는다.

## 1단계 — 계약이 있는가

```bash
cd "$TB" && grep -n "^workspace:" contracts/*.yaml        # ★전부 보고 사람 눈으로 고른다★
```

**완전일치 grep 한 방으로 끝내지 않는다.** `workspace:` 는 절대경로 한 줄이라
중첩(`a_ws/a_ws`)·심볼릭·끝 슬래시·머신 이전 어느 하나에도 안 맞는다. 안 맞으면
「계약 없음」으로 보이는데, **딱 맞는 계약이 이미 있는데도 새로 만들러 가는 것**이
가장 나쁜 실패다(멈추지 않고 엉뚱한 걸 만든다).

판단 순서는 이렇다.

1. `workspace:` 가 `$WS` 와 같으면 → 그 계약. 2단계로.
2. 아니면 **후보를 좁혀 사용자에게 확인받는다** — 경로 끝 이름이 비슷하거나,
   계약의 `package`/`executable` 이 `$WS` 의 `setup.py` 에 있는 것. 확인되면
   그 계약의 `workspace:` **한 줄만** 고쳐 쓴다(계약을 새로 만들지 않는다).
   패키지 이름까지 바뀌었으면 `package:` 도 같이 고친다 — 계약이 진짜 패키지명을
   적지 않으면 `ros2 run` 이 그냥 실패한다.
3. 후보가 하나도 없을 때만 새 워크스페이스다 → **[attach.md](attach.md) 를 읽고
   그대로 한다.** 계약 초안을 만들고 나면 반드시 사용자 확인을 받는다 — 계약이
   틀리면 잰 자리가 엉뚱한데도 표는 멀쩡해 보인다.

## 2단계 — 돌리기 전에 막힐 것을 본다

`doctor` 가 ROS·빌드·가중치·영상·계약을 한 번에 본다. **아무것도 바꾸지 않는다.**

```bash
cd "$TB" && python3 -m tb.run doctor --contract contracts/<계약>.yaml \
    --video /절대/경로/영상.mp4
```

「판정: OK」가 아니면 **먼저 그것부터 고친다.** 특히:

- **실행파일 ❌** — 대상을 빌드해야 한다: `python3 -m tb.run build --contract …`
  (파이썬만 고쳤으면 `--symlink-install` 이라 빌드 불필요)
- **가중치 ❌ / 계약이 요구하는 파라미터 ❌** — `local.yaml` 의 경로를 고친다.
  ★백엔드를 낮춰서 통과시키지 않는다★ — `.engine` 을 `.pt` 로 바꾸면 지연도 마스크도
  실차와 다른 것을 재게 되는데 표는 그대로 멀쩡해 보인다.

## 3단계 — 실행

**시나리오 파일을 만들지 않는다.** 영상 경로와 구간을 인자로 준다.

```bash
cd "$TB" && python3 -m tb.run run \
    --contract contracts/<계약>.yaml \
    --video /절대/경로/영상.mp4 \
    --start 300 --limit 900 \
    --note "정지선에서 제때 서는지" \
    --out "$WS"
```

| 인자 | 언제 |
|---|---|
| `--start` / `--limit` / `--stride` | 사용자가 **구간**을 말했을 때("정지선 접근 구간만") |
| `--note` | ★항상★ — 사용자가 말한 「무엇을 보려는가」를 그대로. 결과에 남는다 |
| `--out "$WS"` | ★항상★ — 결과를 워크스페이스의 `testbed_results/` 로 보낸다 |
| `--mode realtime` | **타이밍**을 볼 때. 기본 `lockstep` 은 벽시계와 무관하게 같은 결과를 준다 |
| `--param 노드.이름=값` | 기능 하나를 끄고 대조군을 만들 때 (`--param perception.enable_x=false`) |
| `--perturb blur\|dark\|noise` | 강건성 — 같은 장면을 흐리게/어둡게 넣어 얼마나 무너지는지 |
| `--preset presets/<이름>.yaml` | 자주 쓰는 조합(영상·구간·파라미터). 인자가 언제나 이긴다 |

- **디버그 영상은 기본으로 남는다**(런당 2~7MB). 끄지 않는다 — 나중에 "그때 노드가
  뭘 봤나"를 물으면 답할 방법이 그 mp4 뿐이다.
- 오래 걸린다(영상 길이 × 프레임당 처리). **백그라운드로 돌리고 기다린다.**

## 4단계 — 결과를 읽는다 (여기가 본론이다)

판정표가 없으므로 **네가 읽고 말해야 한다.** 순서를 지킨다.

1. **「행 N」을 먼저 본다.** 행이 0 이면 그 아래 모든 숫자는 빈 입력에서 나온 것이다.
   노드 로그(`runs/<런>/<노드>.log`)와 「계약 정합」을 먼저 본다.
2. **「계약 정합」 표.** `❌ 불일치` 면 숫자를 논하기 전에 **계약의 그 `path:` 한 줄**을
   고치고 `reanalyze` 한다. `🔁 대체경로` 는 정상(마이그레이션 중), `· 미수신` 은 그
   토픽이 한 번도 안 왔다는 뜻이다.
3. **「받는 쪽 게이트 통과율」.** 차선을 봤는가가 아니라 **받는 쪽이 실제로 썼는가**다.
   인지가 좋아도 게이트를 못 넘으면 주행에 한 프레임도 기여하지 않는다 —
   최대 병목 단계가 곧 다음에 손댈 곳이다.
4. 신호 통계 · 단계 전이 · θ 품질 · 노드 로그.
5. **디버그 영상**을 사용자에게 알려 준다 — 숫자가 이상할 때 확인할 유일한 그림이다.

읽은 것을 **사용자의 말("정지선에서 제때 서는지")에 대한 답**으로 옮긴다.
숫자를 나열하지 말고, 무엇이 병목이고 어디를 보면 되는지 말한다.

**대상 워크스페이스 코드는 사용자가 따로 지시할 때만 고친다.**

## 5단계 — 다시 돌릴 때

| 하고 싶은 것 | 명령 |
|---|---|
| 코드 고친 뒤 전후 비교 | 같은 인자로 한 번 더 돌리고 `python3 -m tb.run diff <런A> <런B>` |
| 계약을 고쳐 과거 런을 다시 읽기 | `python3 -m tb.run reanalyze <런>` (`raw.jsonl` 이 남아 있다) |
| 옛 런의 디버그 영상 | `python3 -m tb.run replay <런>` — 영상은 실행 중에만 잡힌다 |
| 결과를 다시 내보내기 | `python3 -m tb.run export <런> --out "$WS"` (덮어쓴다) |
| 노드가 선언한 파라미터 보기 | `python3 -m tb.run params --contract <계약>` |
| 대상 빌드 | `python3 -m tb.run build --contract <계약>` |
| 테스트베드 자체 검사 | `python3 -m tb.selftest` (ROS·영상 불필요) |

`diff` 는 **판정하지 않는다** — 신호별 차이만 낸다. 그게 회귀인지 개선인지는 네가 말한다.
두 런의 조건(영상·구간·파라미터·기하)이 다르면 표 위에 경고가 붙는다. 그때는 숫자를
비교하지 말고 조건을 먼저 맞춘다.

## 카메라 보정은 웹앱이 한다

IPM 사각형·ROI·픽셀↔미터·BEV 기준선을 맞추는 일은 손으로 보면서 해야 한다.

```bash
cd "$TB" && python3 -m tb.run app      # 별도 창 (또는 web — 브라우저)
```

**사용자가 "카메라 값이 안 맞는 것 같다"고 하면 이 화면을 띄우라고 안내한다.**
값을 대신 지어내지 않는다 — 사각형이 차선 위에 놓였는지는 사람이 봐야 안다.

## 절대 하지 않는 것

- **임계값을 지어내지 않는다.** 이 도구는 판정하지 않는다. "이 값이면 합격"이라는
  기준이 필요하면 **근거를 먼저 말하고 사용자에게 확인받는다.**
- **재는 쪽을 고쳐 숫자를 좋게 만들지 않는다.** 계약의 `path:`·게이트 상수를 고치는 것은
  「잰 자리가 틀렸을 때」뿐이고, 그때도 근거를 말한다.
- **`tb/*.py` 와 `web/*` 에 대상 워크스페이스의 토픽명·필드 배치·노드명·파라미터명을 쓰지
  않는다.** 전부 계약 YAML 에만 있다.
- **결과를 머신 너머로 옮겨 비교하지 않는다.** GPU·가중치·영상이 다르면 값이 달라진다.
  `run_env.json` 이 그 판단의 근거다.
- 테스트베드에 외부 의존성을 추가하지 않는다(표준 라이브러리만 — 현장에 네트워크가 없다).

`$TB/README.md` 에 전체 설계와 절차가 있다.
사람이 읽는 사용 설명은 [USAGE.md](USAGE.md) — 사용자가 "이 스킬 어떻게 쓰냐"고 물으면 거기를 가리킨다.
